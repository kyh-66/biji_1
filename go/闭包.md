在 Go 语言中，**闭包（Closure）** 是一种特殊的函数。简单来说：

> **闭包 = 函数 + 该函数所绑定的外部自由变量**

当一个匿名函数引用了在其外部定义的变量时，这个函数就和它引用的外部变量形成了一个整体，这个整体就被称为闭包。即使外部函数已经执行完毕退出了，闭包引用的变量依然会“存活”在内存中，供闭包继续访问和修改。

## 一个直观的例子

我们来看一个最典型的计数器例子：

Go

```
package main

import "fmt"

// addUpper 返回一个函数，这个返回的函数就是一个闭包
func addUpper() func(int) int {
	var n int = 10
	return func(x int) int {
		n = n + x // 引用了外部函数的变量 n
		return n
	}
}

func main() {
	f := addUpper() // 此时 f 就是一个闭包

	fmt.Println(f(1)) // 输出 11 (10 + 1)
	fmt.Println(f(2)) // 输出 13 (11 + 2)
	fmt.Println(f(3)) // 输出 16 (13 + 3)
}
```

### 这里的关键点：

1. `addUpper()` 已经执行完毕并返回了，但变量 `n` **并没有被销毁**。
    
2. 每次调用 `f(...)` 时，使用的都是同一个 `n`，并且 `n` 的状态在被累加和保留。
    

## 闭包的底层机制：引用传递（而不是值拷贝）

闭包捕获外部变量时，使用的是**引用（指针）**，而不是在创建闭包时拷贝变量的值。这意味着闭包内部修改变量会影响外部，反之亦然。

来看一个经典的“踩坑”例子（在 Go 1.22 之前非常常见）：

Go

```
package main

import (
	"fmt"

	"time"
)

func main() {
	// 多个 Goroutine 共享同一个变量 i
	for i := 0; i < 3; i++ {
		go func() {
			fmt.Println(i) // 捕获的是变量 i 本身
		}()
	}

	time.Sleep(100 * time.Millisecond)
}
```

- **现象**：由于 Goroutine 启动需要开销，当闭包实际运行时，`for` 循环很可能已经跑完，`i` 变成了 `3`。因此输出通常会是 `3, 3, 3`。
    
- **解决方案**：将 `i` 作为参数显式传给闭包，或者在循环内部重新声明局部变量：
    

Go

```
for i := 0; i < 3; i++ {
	go func(val int) {
		fmt.Println(val) // val 是每次循环独有的值拷贝
	}(i)
}
```

> **注**：Go 1.22 对 `for` 循环的变量作用域做了优化，每次循环迭代都会创建一个新的 `i` 实例，从而从语言层面修正了这个经典陷阱。但理解“引用捕获”的原理解依然至关重要。

## 闭包的核心应用场景

闭包在 Go 开发中有非常广泛的实用场景：

### 1. 状态保持与工厂函数

无需定义包含成员变量的 `struct`，仅靠闭包就能维护内部状态（如上面提到的计数器，或者生成特定前缀/后缀的生成器）。

Go

```
func makeSuffix(suffix string) func(string) string {
	return func(name string) string {
		if !strings.HasSuffix(name, suffix) {
			return name + suffix
		}
		return name
	}
}

// 自由创建专门处理 .jpg 和 .html 的工具函数
addJPG := makeSuffix(".jpg")
fmt.Println(addJPG("avatar")) // avatar.jpg
```

### 2. 函数式编程与中间件/装饰器

在 HTTP Web 框架（如 Gin、net/http）中，中间件通常以闭包的形式存在，用以包装原始 Handler，注入日志记录、权限校验或延迟处理（`defer`）等逻辑。

Go

```
func Logger(next http.HandlerFunc) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		next(w, r) // 执行核心逻辑
		log.Printf("Request processed in %v", time.Since(start))
	}
}
```

## 总结

- **本质**：函数 + 绑定的外部变量上下文。
    
- **内存存储**：被闭包引用的局部变量会发生**内存逃逸**（从栈分配逃逸到堆分配），从而在外部函数返回后依然保持生存。
    
- **特性**：闭包捕获的是变量的**地址（引用）**，多次调用同一个闭包会共享并修改被捕获变量的状态。
--------------------------------------------------------------------------------

因为这里的 `makeSuffix` **并不是一个普通函数，而是一个“生产函数的工厂”**（也叫高阶函数）。

两个 `func` 分别代表了**两层函数**：

Go

```
// 第一层 func：定义制造者 makeSuffix
func makeSuffix(suffix string) func(string) string {
    //                                 ^^^^^^^^^^^^^^^^^^
    //                                 这是第一层函数的【返回值类型】

	// 第二层 func：定义实际被生产出来的那个“匿名函数”并把它 return 出去
	return func(name string) string {
		if !strings.HasSuffix(name, suffix) {
			return name + suffix
		}
		return name
	}
}
```

### 2. 拆解运行过程

如果你去调用它，分为两步：

Go

```
// 第一步：调用第一层 func (makeSuffix)
// 传入 ".jpg"，制造出一个专属的追加函数，赋值给 addJPG
addJPG := makeSuffix(".jpg") 

// 第二步：调用第二层 func (匿名函数)
// 此时 addJPG 本身就是第二层的 func(name string) string
result := addJPG("avatar") // 结果为 "avatar.jpg"
```

### 为什么不直接写成一个普通函数？

你可能会问：为什么不直接写一个 `func addSuffix(name string, suffix string) string` 呢？

**答案是：为了“绑定状态”，实现定制化。**

如果用闭包这种写法：

1. 你可以在程序初始化时，先配置好各种处理规则（比如 `addJPG := makeSuffix(".jpg")`、`addPNG := makeSuffix(".png")`）。
    
2. 在后面的业务代码里，你只需要把 `addJPG` 当作一个简单的工具函数传给别人用，**使用它的人根本不需要关心 `suffix` 是什么**，因为 `suffix` 已经被第一层函数“塞入”并锁在闭包里了。
