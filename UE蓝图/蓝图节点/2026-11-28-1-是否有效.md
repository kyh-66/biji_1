# 是否有效（Is Valid）

判断一个对象引用到底还能不能用——不只是"不是空"，还要看它是不是已经被销毁了。

## 干什么用的

`Is Valid` 是纯节点（没有执行引脚），输入一个对象引用，返回一个 bool。

它比"引用 != 空"多查了一层：对象虽然指针还在，但已经被 `Destroy Actor`、
或者正在被 GC 回收（pending kill），`Is Valid` 会返回 `false`。
对应的反向节点是 `Is Valid` 后面的 `NOT`，或者用 `Is Valid` 接分支的`假` 引脚。

## 输入 / 输出

| 引脚 | 类型 | 说明 |
|---|---|---|
| Input Object | Object Reference | 要被检查的对象引用，任何 UObject 派生类都行 |
| Return Value | Boolean | `true` = 对象存在且未被销毁 |

## 典型场景

- **缓存了某个 Actor 的引用**（比如"当前锁定的敌人"），用之前先 `Is Valid` 一下，
  再取它的位置 / 血量。目标被打死了引用还在，这里就是防线。
- **异步之后回来用对象**：`Set Timer by Event` 的回调晚了半秒，被延迟的 Actor 早没了，
  回调里第一件事就是 `Is Valid`。
- **动态生成的 Actor 做 UI 追踪血条**，每帧把引用喂给 `Is Valid` + 分支，比 Cast 便宜。
- 检查 `Spawn Actor` 的返回值——生成失败（位置被占、类没设）时返回空。

## 坑

- **不等于 Python 里的 `is not None`**。被销毁的 Actor，变量的指针可能还挂着，
  直接比较"!= 空"会得到 `true`，然后一取位置就崩或者读到垃圾值。
- **只查 Actor 自己，不查它的组件**。Actor 活着但组件被 `Destroy Component` 了，
  `Is Valid` 对 Actor 仍然返回 `true`，组件引用要单独查。
- **别把 `Is Valid` 当"逻辑上还能用"**。Gameplay 上"已经死了但还没销毁"的敌人，
  `Is Valid` 是 `true`——这种要自己加 `Is Alive` 之类的状态位，两个条件一起判。
- **对纯数据对象没意义**。UObject 里非 Actor 的（比如 DataAsset）生命周期由引用计数管，
  它不会"半死"，这时候 `Is Valid` 和 `!= 空` 差不多。
- 放在 Tick 里查没问题，纯节点不产生开销意义上的 Exec 调用，但别为了它 Cast 一遍——
  引用类型本来就能直接喂进去。
