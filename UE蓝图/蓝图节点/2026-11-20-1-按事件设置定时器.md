# 按事件设置定时器（Set Timer by Event）

按"事件"而不是"函数名"启动一个定时器，时间到的时候回调你指定的自定义事件。

## 干什么用的

游戏里需要"过一会儿再做某事"的时候用：延迟开火、冷却结束、每隔几秒刷新一次 AI 状态。
它和 Delay 的区别是：**它不占用当前执行链**，而且你可以拿到 Handle 手动取消。

- Delay：卡住当前流程，节点后面的东西等它跑完。简单，但没法取消。
- Set Timer by Event：立刻返回，时间到了才跳去执行你的事件。可以取消、可以循环。

## 输入 / 输出

| 引脚 | 类型 | 说明 |
|---|---|---|
| 执行（Exec） | Exec | 进来就注册/覆盖定时器 |
| 事件（Event） | Delegate | 要绑定的自定义事件，右键选择"创建事件" |
| 时间（Time） | Float | 秒。小于等于 0 会立刻触发 |
| 循环（Looping） | Boolean | 勾上就是每隔 Time 触发一次，不勾只触发一次 |
| 返回值（Return Value） | Timer Handle | 用来取消它的句柄，**一定要存下来** |
| 执行（Exec） | Exec | 注册完立刻从这里继续走 |

取消用 **按句柄清除且作废定时器（Clear and Invalidate Timer by Handle）**，把 Handle 接进去。

## 典型场景

- **武器冷却**：开火时用 0.5 秒的定时器，时间到了把"可以开火"的布尔值设回 true
- **AI 巡逻节奏**：Looping 勾上，每 2 秒跑一次"挑下一个巡逻点"的事件
- **UI 提示自动消失**："拾取成功"横幅显示 1.5 秒，用一次性定时器收回

## 坑

- **同一个对象重复调用会覆盖上一次**：用同一个事件连续调两次，前一个定时器被顶掉了，不会叠加。想叠加就得用不同的委托或自己管 Handle。
- **对象销毁时定时器会自动清掉，但你要确认绑定的事件属于谁**。事件绑在一个会被销毁的 Actor 上没事；绑在一个长命对象上去回调已销毁的 Actor，就是空指针。
- **Looping 的定时器不会因为你切关卡自动停**，切图前记得 Clear 掉，否则 GameInstance 上的定时器会一直往已经不存在的 UI 上回调。
- **Time 用 World Time 还是 Real Time**：默认是游戏时间，游戏暂停（Pause）后定时器也停。要"暂停时照样计时"（比如存档倒计时），得用 **按事件设置定时器（Set Timer by Event，但底层用 SetTimer 的 bUseRealTime）** 那套，蓝图节点上不直接暴露，要进 C++ 或用自定义节点。
- **别用 0.0 当"每帧"用**，每帧都跑的请用 Tick，定时器堆多了开销比 Tick 还大。
