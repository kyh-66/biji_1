# 添加移动输入（Add Movement Input）

给 Pawn 的移动组件塞一份"这个方向、这个力度"的输入，由移动组件在下一帧决定怎么走。

## 干什么用的

它不是瞬移，也不是设置速度。它只是往移动组件里**追加一个方向向量 + 一个 0~1 的缩放**，剩下的加速、减速、碰撞、爬坡、贴地全交给 Character Movement（或 Floating Pawn Movement）去算。

所以它天然会跟碰撞、重力、导航这些系统配合，而不是绕过它们。

## 输入 / 输出

| 引脚 | 类型 | 说明 |
|---|---|---|
| Target | Pawn | 一般是 Self；必须是带移动组件的 Pawn |
| World Direction | Vector | **世界空间**方向，内部会归一化，长度无意义 |
| Scale Value | Float | 这个方向的力度，通常 0~1，一般直接喂输入轴的 Axis Value |
| Force | Boolean | 勾上表示"强制推"，忽略 Scale Value 的轻重，按满力度走（被击退、被风吹这类） |

输出：**没有执行引脚，也没有返回值**。它是纯数据节点，调用完就没了，效果发生在移动组件的下一次更新里。

## 典型场景

- **角色移动**：InputAxis MoveForward → Break Rotator 取 Controller 的 Yaw → Get Forward Vector → 接 World Direction，Axis Value 接 Scale Value
- **推箱子 / 传送带 / 风场**：在 Box 重叠里对角色 Add Movement Input，Force 勾上，让外力不被玩家的输入速度稀释
- **过场里强行挪人**：配合 Disable Input 后自己喂方向，比 Set Actor Location 更像"走"过去

## 坑

- **只调一次只走一帧**。它不是"开始移动"，是"这一帧想往哪走"，必须每帧（Tick 或输入事件）持续喂，否则角色点一下就停。
- **没有 Controller 就不响应**。PlayerController 没 Possess、或者输入被 Disable 掉时，Character 上的 Add Movement Input 不会生效——调试时先看 Possess 和 Input 状态。
- **方向要用世界空间**。直接拿 Actor Forward Vector 会在角色转身后和输入打架；标准做法是从 Controller Rotation 取 Yaw 再算前/右向量。
- **别和 Set Actor Location 混着做移动**。后者会瞬移、穿墙、跳过加速曲线，两者叠用容易出现抖动和卡进地形。
- **Force 不是"更大声地喊"**。它绕过 Scale Value，用来表达不可抗的外力；玩家输入上勾它，摇杆轻重就废了。
