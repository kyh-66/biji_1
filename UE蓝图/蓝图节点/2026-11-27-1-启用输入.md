# 启用输入（Enable Input）

让这个 Actor 从指定玩家的 Player Controller 那里收键鼠/手柄输入。

## 干什么用的

Pawn 被 Controller 控制时输入是自动通的；其他 Actor（道具、箱子、载具、可交互物）想直接监听按键，就得自己向 Player Controller 注册——这就是 Enable Input 干的事。它有配对的 Disable Input。

## 输入 / 输出

| 引脚 | 类型 | 说明 |
|---|---|---|
| 执行输入 | exec | 触发 |
| Target | Actor | 要接收输入的 Actor，一般连 self |
| Player Controller | Player Controller | 把输入挂到哪个玩家身上，不能空 |
| 执行输出 | exec | 接着往下走 |

Disable Input 的引脚完全一样。

## 典型场景

- 玩家进到载具/炮塔附近按 E 接管控制
- 打开一个只有这个 Actor 关心的快捷键：比如摄像机切换、对讲机面板
- 小游戏里让一个非 Pawn 的 Actor 临时响应方向键

## 坑

- **Player Controller 不能是空引用。** BeginPlay 里直接 `Get Player Controller` 有时拿到的是还没 Possess 的 PC，输入挂上去也不生效。稳妥做法是在 Possess 之后，或者等 PlayerController 的有效事件再 Enable。
- **别把索引 0 写死。** 分屏和联机下，每个客户端本地的 Player Controller 索引不一样，`Get Player Controller 0` 在自己机器上是对的，别人的机器上就挂错了人。取本地玩家更稳。
- **换 Controller 就断了。** 玩家死了重生、Possess 到新 Pawn，Player Controller 可能还是同一个，但如果中间重建过，之前 Enable 的输入要重新挂一次。
- **开了 UI 不等于输入还在。** 用了 Set Input Mode UI Only 之后按键被 UI 吃掉，看起来像 Enable Input 失效，其实不是。
- **记得配 Disable Input。** 不关的话多个 Actor 同时抢同一个键，按一下触发一堆，排查起来很烦。
- **它管的是本地输入。** 服务器上调用没有意义，要保证在拥有这个玩家的客户端上执行；联机时按键的判定一般走 RPC 回服务器，别在客户端直接改状态。
