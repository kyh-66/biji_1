# 让AI自己走过去（AI Move To）

让被 AI 控制器控制的 Pawn 沿着导航网格走到目标点或目标 Actor，并告诉你走到了没有。

## 干什么用的

它不是"瞬移"，是给 AIController 下一条寻路指令：从当前位置规划一条路径，沿路移动过去。
底层是 AIController 的 MoveTo，所以**必须有人占着这个 Pawn 且那个控制器是 AIController**，玩家控制器直接调是走不动的。

## 输入 / 输出

| 引脚 | 类型 | 说明 |
|---|---|---|
| Target Actor | Actor | 要追的目标。填了它，Target Location 会被忽略 |
| Target Location | Vector | 固定目标点，世界坐标 |
| Acceptance Radius | Float | 判定"到了"的距离，单位厘米 |
| Stop on Overlap | Bool | 到了以后要不要停下来；关了就会一直顶着目标 |
| On Success | Exec | 成功走到（进入接受半径） |
| On Fail | Exec | 寻路失败或中途被打断 |

没有返回值，判断结果只能靠 On Success / On Fail 这两根执行线。

## 典型场景

- 小怪追玩家：目标接玩家，Acceptance Radius 给大一点（比如 150），进范围就切攻击
- 巡逻点：目标接固定 Location，走完一个点再发下一个
- 过场里 NPC 走位：一次性调用，等 On Success 再触发下一段
- 配合行为树时一般不用它，用 BT 的 Move To 任务，节点本身是被打断友好的

## 坑

1. **没有 NavMesh 就静默失败**。场景里得有 NavMeshBoundsVolume 并 Build 过路径，不然 On Fail 一闪而过，看着像没执行。先按 `P` 看绿色导航网格。
2. **Acceptance Radius 默认太小**。默认只有 5 厘米，角色胶囊体半径通常三四十，结果就是"永远到不了"，一直卡在 On Fail。给 50~150 更符合直觉。
3. **两个目标都填时 Actor 优先**，Location 被无视。想走到一个点，就把 Target Actor 留空。
4. **它是"发一次指令"，不是持续追踪**。目标移动了不会自动重规划，得自己再调一次，或者用行为树/`MoveTo` 的持续更新。
5. **没有 AIController 就一定失败**。Pawn 被玩家控制器 Possess、或者根本没 Possess，都会走不动。
6. **只管平面寻路**。没有 NavLink 的情况下不会跳、不会爬；落差大或者要跨沟的地方，得自己加 Nav Link Proxy。
7. **别每帧调**。每帧发起一次寻路会一直重置路径，角色原地抖动；一个目标发一次，或者用计时器隔几秒重发。
