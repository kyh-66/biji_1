# 数值别焊死在蓝图里：什么时候该上 DataTable，什么时候不该

蓝图里到处是 `Set Base Damage = 25` 这种常量，改一个数要翻八个蓝图、编译两次、还容易改漏。把数值抽成表格是个常见解法，但它不是免费午餐。

## 什么情况下值得抽

- 同一类东西有几十上百条数据（武器、技能、掉落表、敌人属性），而且会反复调
- 数值策划不写蓝图，只想要一张能填的 Excel
- 同一套逻辑要跑不同配置（难度档位、模式变体）

反过来说：如果全场就三把武器、两年不改一次，抽表只增加一层间接，直接在蓝图里有名字的变量反而更好查。

## 怎么落地

1. 建一个结构体，父类选 `Table Row Base`（必须，不然 DataTable 不收）
2. 新建 DataTable，Row Struct 选它
3. 每行一个 Row Name（FName），用 `Get Data Table Row` 按名字取，或 `Get Data Table Row Names` 遍历
4. 取出来的是结构体副本，改完记得写回去或者重新取，别指望改副本影响表

## 坑

- **改字段名 = 数据全丢**。把结构体里 `Damage` 改成 `BaseDamage`，表里那列直接空掉，不留备份就等着重填。
- **按字符串查是软失败**。Row Name 打错一个字母，`Get Data Table Row` 返回 false，拿到的是默认结构体，看起来像"数值变成 0 了"。关键路径上加个 Branch 打日志，别静默吞掉。
- **整张表常驻内存**。DataTable 是加载即全量反序列化，不是按行懒加载。几千行的掉落表跟着关卡一起进内存，包体和内存都要算进去；真的大就拆表或者上 Primary Asset Label 做分包。
- **打包后改不了**。DataTable 打进包里就是只读的，想做热更数值得另外走 DataAsset 或者外部配置，别指望打完包还能改表。
- 别拿 DataTable 当状态存。它是配置，不是存档；运行时改行只活在当前会话。
