# 先灰盒再抛光：玩法没验证之前，别做能看的东西

新人最常见的顺序是反的——先搭一张漂亮的场景，再往里面塞玩法。结果玩起来不对，改一次要动全部美术资源，
最后不是舍不得改，就是改到美术全崩。正确的顺序是：**用最丑的东西把玩法跑通，再一层层往上贴皮。**

## 灰盒阶段到底在验证什么

灰盒（Blockout / Greyboxing）不是「先摆几个方块凑合一下」，它是在回答几个很硬的问题：

- **距离对不对**：跳跃能过多宽的沟、子弹射程和掩体间距是不是匹配玩家反应速度
- **视线对不对**：玩家从出生点能看到什么、该看到什么、不该看到什么
- **节奏对不对**：这段路走多久、什么时候出现第一个敌人、什么时候给喘息
- **空间够不够**：体积、碰撞、导航网格（NavMesh）能不能正常生成

这几件事只要有一件没定，美术资产就是在赌。赌赢了是运气，赌输了就是返工。

## 具体怎么落地

1. **只用引擎自带的基础几何体**（Cube / Cylinder / 平面），不导入任何美术资产
2. **玩家角色用胶囊体 + 临时动画**，能跑能跳能开枪就够了
3. **给灰盒物件统一的识别材质**：可走 / 不可走 / 可交互 / 关卡边界，四色区分，一眼看懂空间语义
4. **先把「走一遍」跑通**：从出生点走到终点，中间不卡住、不掉出地图、导航能连上
5. **再验证玩法循环**：打一场、赢一次、死一次，确认数值和空间是咬合的
6. **最后才是美术介入**：替换模组、加细节、做灯光

## 几条摸出来的经验

- **灰盒的尺寸就是最终尺寸。** 美术进来之后只会往里加细节，不会允许你把走廊再拓宽 200 单位——因为已经排满资产了。所以灰盒阶段的尺寸必须当成合同。
- **比例尺要在一个真实的人体视角下看。** 俯视截图里看着很宽敞的房间，第一人称走进去往往窄得像柜子。灰盒阶段一定要用游戏内相机走一遍。
- **灯光在灰盒阶段只做一件事：让人看清路。** 别在灰盒上打氛围光，那会掩盖「这里太黑玩家会迷路」这种真问题。
- **碰撞和视觉要分开想。** 灰盒物件的碰撞体先用简单盒体，等美术替换模组时再根据模型调——但尺寸基线不能变。
- **阶段要有明确的结束标志。** 比如「策划和程序都完整通关一次并且没有提出空间问题」，否则灰盒会无限期地「再改一点点」。

## 坑

- **灰盒做太好看的陷阱。** 灰盒一旦精致，团队就会下意识保护它，不敢改结构。**丑是特性，不是缺陷。**
- **只在编辑器视角里验证。** 编辑器里那个自由飞行相机是所有比例错觉的源头。
- **跳过灰盒直接做垂直切片。** 垂直切片（Vertical Slice）是给外部看「这游戏长这样」，前提是玩法已经验证过了；拿它当探索工具，成本高一个数量级。
- **关卡设计和美术同时开工。** 两边都在改尺寸，最后谁也定不下来。定好灰盒锁版本，美术再进场。
