# 性能优化得先分诊：帧预算是谁的

优化最容易犯的错不是不会调，是**在错的地方调**。帧时间就那么多，先花十分钟搞清楚它是被
谁吃掉的，往往比瞎改一通省下几天。

## 一条固定的分诊流程

1. **先定点**：找一张固定的参考场景（同一个存档、同一个出生点、同一段镜头运动），
   把帧率上限锁死（`t.MaxFPS`），别让引擎靠掉帧骗你。之后所有对比都在这张图上做。
2. **看总账**：`stat unit` 一行里 Frame / Game / Draw / GPU 分开。
   - Game ≈ Draw 即 **CPU 主线程瓶颈**（蓝图 Tick、AI、物理、动画）
   - GPU 明显最高 = **GPU 瓶颈**，去调渲染参数才有意义
   - 两个都高但 Frame 更差 = 在等对方，先解决高的那个
3. **再拆细**：CPU 侧 `stat Game` 看是哪一块，`Unreal Insights` 抓一段 trace 看调用栈；
   GPU 侧 `ProfileGPU`（或 `stat gpu`）看 RenderTarget / Shadows / BasePass 各占多少。
4. **只改最大的那块**，改完回到第 2 步复测。一次只动一个变量。

## 经验

- **GPU 瓶颈的时候改蓝图等于白干。** 反过来，CPU 瓶颈的时候把阴影分辨率砍一半也白干。
  这一步不确认，后面全是碰运气。
- **看 1% low，不看平均帧。** 玩家骂的"卡"几乎都是尖刺，平均 60 帧但每隔两秒掉一次到 20，
  体验比稳定 45 还差。抓尖刺靠 trace，`stat unit` 的平均值看不出来。
- **编辑器里测出来的数只能做横向对比。** PIE 有编辑器开销、有 GEditor 的额外绘制，
  打包之后的绝对数值完全不一样。要绝对值，必须打包 Development 或 Test 版测。
- **渲染分辨率是性价比最高的一刀。** 一次 Screen Percentage 或后处理质量的调整，
  通常比折腾一堆材质节点立竿见影；先确认是不是真的 GPU bound，再动它。
- **CPU 上最常见的是"每帧都干一次的傻事"**：Tick 里 `Get All Actors Of Class`、
  每帧重建字符串、每帧 `Set Text` 触发 UMG 重排、大量独立 Actor 的 Component Tick。
  这些用 Insights 一眼就能看出来，而且改法都很朴素——缓存、事件驱动、关掉 Tick。
- **别为了一个内存指标牺牲可维护性。** 预算（帧/内存）应该在项目开头就定，
  而不是上线前一周才发现 30fps，那时候架构已经改不动了。

## 工作流上的建议

给项目留一个**性能基准场景 + 一份对比脚本**，每周跑一次记录数字。趋势比单次数值重要：
某个版本帧时间突然涨 3ms，比"现在只有 50 帧"更容易定位到是哪次提交干的。
